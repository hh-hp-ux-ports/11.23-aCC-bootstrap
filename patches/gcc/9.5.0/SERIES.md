# gcc 9.5.0 patch series — which of these you actually need

The directory holds seven numbered patches, but **applying all seven is not what the working build
does**, and the numbering alone does not tell you that. Read this before running the series.

| patch | status | why |
|---|---|---|
| **0001** `gprel64-is-invalid-for-shared-objects` | **REQUIRED** | Permanent. `@gprel64` encodes the link-time distance `S - GP`, which on ia64-hpux is not preserved because text and data are mapped independently — so it is wrong in **any** shared object, for **any** linker. gcc itself builds `lto-plugin` as a `.so` even under `--disable-shared`, so this is required even for an executable-only build. |
| **0002** `LP64-only-specs-and-reject-milp32` | **REQUIRED** | LP64-only specs, hardcoded `hpux64` startfiles, explicit LP64 `-L` paths, and a real error message for `-milp32` (whose codegen ICEs on this target). Pairs with `--disable-multilib`. |
| 0003 `disable-RTL-passes-that-crash-this-target` | **REMOVED** (2026-08-03, Hugo) | Not in the shipped set. |
| **0004** `gcov-tool-hpux-nftw-passes-struct-FTW-by-value` | **REQUIRED** | HP's `nftw` passes `struct FTW` **by value**, not by pointer. |
| 0005 `diagnostic-let-libbacktrace-find-the-exe-via-env` | diagnostics only | Was an investigation aid, not needed to build. |
| 0006 `toplev-SIGSEGV-handler-printing-ia64-fault-context` | diagnostics only | Same. |
| 0007 `ipa-devirt-inline-the-pointer-hash` | **RETIRED** | Proven unnecessary by a completed build. |

⇒ **The shipped patch set is `0001 + 0002 + 0004`** — 3 files. 0005/0006 are kept because the
reasoning in them is useful when something goes wrong, not because the build wants them.

## Verifying before you trust them

All seven were confirmed to apply cleanly to a **pristine gcc 9.5.0 release tarball** with
`patch -p1` on 2026-08-11. That check exists because two of them had previously been published
broken:

- **0001 did not apply at all** — its hunk header claimed 23 new lines where the body had 24, so
  `patch` rejected it with `malformed patch`. Regenerated by applying the change to a pristine
  `ia64.c` and letting `diff -u` compute the counts, rather than hand-editing them.
- **0002 applied to nothing (3/3 hunks failed) and was an earlier, incomplete revision** — it was
  missing the LP64 library search paths (`PATCH 05c`, `-L/usr/lib/hpux64 -L/lib/hpux64
  -L/usr/ccs/lib/hpux64`) that the working build depends on; without them the link finds
  `/usr/ccs/lib` instead of `/usr/lib/hpux64`, where `libc.so` actually lives. Regenerated from the
  header **as installed by the working build** (`toolchain_archive/gcc95-hld-2026-07-31.tar`),
  diffed against the pristine release.

⚠️ **Do not regenerate these against `gnu_tarballs/gcc-9.5.0/` on the NFS share — that tree is
already partially patched** (`hpux.h` carries the PATCH markers, `ia64.c` does not). Diffing against
it silently produces an empty patch for `hpux.h`. Always use the release tarball as the reference.
